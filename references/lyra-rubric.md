# 优化评级 / 迭代 / 接收方适配（Lyra 机制落地）

来源：Lyra Prompt Optimizer 的前端契约（`/api/prompt-optimizer/{optimize,iterate,test}` 的入参与返回字段），翻译成离线可执行的标准。

## 1. 两种提示词类型（先判这个，改法完全不同）

| 类型 | 是什么 | 优化重心 |
|---|---|---|
| **user prompt** | 一次性的任务说明（「写封拒会议的邮件」） | 目标动词要可验收、输入/产出格式、长度与语气约束、验收标准 |
| **system prompt** | 定义 AI 长期角色与行为（「你是审稿专家」） | 身份边界（做什么/**不做什么**）、冲突时的优先级、输出格式、越界时的行为、拒答条件 |

判错类型的典型症状：把 system prompt 优化成一次性任务（角色约束被写成「请帮我审这段代码」），或反过来把任务写成泛泛的角色设定。

## 2. 级别（optimizationLevel）

| 级别 | 对应 | 表现 |
|---|---|---|
| `basic`（默认） | Quick improvements | 修目标/输入/产出三处硬伤，行数几乎不变 |
| `advanced` | Professional optimization | 补验收标准、边界、输出 schema，加结构化小节 |
| `expert` | 详尽 | 加示例（few-shot）、反例、失败处理、自检清单 |

**默认 basic。** 把每条提示词都做到 expert 是负担；只有用户明确要「详细/专业」，或这条提示词要用在生产/自动化链路里，才升级别。

## 3. 评分（模块 1 里的 `【评分 原 XX → 优后 XX】`）

五维，各 0-20，加总 100。只标缺口，不解释：

1. **目标明确** —— 有可验收的动词，能判断做没做完
2. **输入完整** —— 素材/上下文/约束给全了，或明确说明去哪拿
3. **产出规格** —— 格式、长度、语言、交付形态（文件/表格/JSON）
4. **边界与禁区** —— 不许做什么、不确定时怎么办
5. **结构与冗余** —— 分层清晰、无重复、无软词

打分口径：优化后的分数**不得**靠「写得更长」拿分。长度增加只在补了四要素缺口时算合理。原分 70+ 通常只需 basic 微调；原分 <40 往往要拆结构。

## 4. 迭代（v2、v3…）

用户说「再改一版」或「按 X 方向再改」→ 复用四模块，标题行写 `## v<N> · 目标：<goal>`，模块 1 末尾带上一版与新版分数（`【v2: 62 → 78】`）。**迭代必须带明确目标**，否则就是重写一遍。

可复用的迭代目标（Lyra 的枚举，直接对号入座）：

| goal | 改什么 |
|---|---|
| `enhance_clarity` | 简化语言、拆长句、去歧义 |
| `improve_structure` | 加小节标题、编号、分隔符，把杂段落归位 |
| `refine_specificity` | 加精确约束与参数（数值、范围、长度、命名） |
| `add_examples` | 补 1-2 个输入输出样例（few-shot） |
| `general_improvement` | 综合提升（用户没说方向时的兜底） |

迭代上限：连改 3 版还没有实质变化（分数没有上升）→ 停下来告诉用户卡在哪一维，别再刷。

## 5. 接收方适配

同一条提示词喂给不同模型，写法偏好不同：

| 接收方 | 写法偏好 |
|---|---|
| 强推理模型（Claude / GPT 类） | 角色 + 任务 + 边界三段式，善用结构化分隔（标题、XML 标签），可以给判断准则而非死规则 |
| 轻量/快速模型（flash 级） | 约束写死、步骤编号、输出格式显式，不依赖「你懂的」；这类模型对模糊形容词敏感 |
| 网页版通用模型 | 通用写法；交给外部服务前**先抹掉**项目名、本地路径、内部架构、人名（脱敏） |

不确定接收方 → 写模型无关版：显式约束 + 分步 + 输出格式，不写特定模型的技巧词。

## 6. 测试对比（Lyra 的 test 端点，离线怎么等价）

Lyra 会把同一任务分别喂给原提示词与优化后提示词，比对输出质量。离线等价物：把两版提示词分别发给**同一个模型**（或同一个子 agent），比对输出差异；差异不明显说明优化没打中要害。注意先脱敏。
